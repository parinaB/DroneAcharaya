# simulation/

MATLAB / Simulink physics model of the MALE UAV piston engine that generates the
synthetic telemetry the ML layer trains on. `model/` and `scripts/` are built
and validated (see `docs/build_plan.md`'s Step 6 log); `calibration/` and
`fault_injection/` never became separate folders in practice — see below.

| Folder | Holds |
| --- | --- |
| `model/` | Simulink plant models (`.slx`): `engine_core`, `crank_resolved_sidecar`, `environment_service`, plus `AeroDieselEngineParameters.m` (the single source of truth for engine constants). |
| `scripts/` | MATLAB drivers, fault generation, and export scripts (`.m`) — dataset generation (`generate_fleet.m`, `run_fleet_missions.m`), fault injection (`fault_class_registry.m`, `compute_health_trajectory.m`), verification (`verify_batch.m`), and one-off single-mission runs (`run_single_mission.m`). |
| `calibration/` | Superseded — engine parameter sourcing lives in `model/AeroDieselEngineParameters.m`'s inline comments and `../contract/parameter-source-table.csv`, not a separate folder. |
| `fault_injection/` | Superseded — fault ramps are generated by `scripts/compute_health_trajectory.m` + `scripts/fault_class_registry.m`, not a separate folder. |
